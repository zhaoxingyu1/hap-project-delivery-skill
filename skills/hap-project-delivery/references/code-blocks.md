# 明道云代码块规范

### 4.3 代码块参数说明

每个参数记录：节点标识、技术键、中文业务含义、值来源、类型与格式、必填与空值处理、示例、下游引用。代码另有版本及实现的规则编号。

输出结构在成功和失败路径上尽量保持稳定。项目可使用英文键配中文值和说明，例如 result 对应“执行结果”、message 对应“结果说明”、processed_count 对应“处理数量”；这是命名建议，不是平台预置字段。

不要把未知处理数量填成 0；0 表示已知没有处理，未知应按已约定的空值或独立状态表达。下游必须能区分成功无数据、业务拒绝、部分完成和技术失败。

## 5. 已查明的代码块文档依据

来源：[明道云官方代码块节点说明](https://help.mingdao.com/workflow/node-code-block/)，查阅日期 2026-10-22。以下是文档信息，未在用户目标环境验证。

| 文档线索 | 对设计的影响 |
|---|---|
| Python 示例从 input 读取，向 output 赋结果；文档要求实际输出键用英文以避免兼容问题 | 输入输出约定必须明确，中文可读性通过说明、注释和结果信息保留；不得断言所有中文键必然报错 |
| 文档列 Python 3.7.5、Node.js 10.16.3，并将 requests 列为可用 Python 模块 | 作为兼容性核对起点；不推断用户环境一定相同，也不猜测库具体版本 |
| 数组输入按字符串处理；多行记录来源有 100 行限制说明 | 明确输入序列化和数据完整性；不把这一条外推成所有 API 的分页上限 |
| 下游引用前需要节点有测试输出并保存 | 节点代码写完与下游参数可用是不同状态；未来需要有受控的操作步骤 |
| 节点执行失败可自动重试一次，设置可关闭 | 设计写入操作时应同时考虑平台重试与代码内重试，避免重复副作用 |

上述限制不能仅凭本地 Python 能运行就认定已满足。项目需要核实时，在明确的测试范围和副作用边界内安排平台检查；若用户暂缓则标记待核实。

### 中文偏好与兼容性的取舍

用户要求是“输入输出注释和参数这些最好用中文，便于查看和排错”。保留该偏好，并将官方输出命名提示作为实际证据：

- 业务说明、注释、参数含义、结果说明和错误解释使用中文。
- 输入键在目标环境支持时用中文；输出技术键默认英文，同时提供中文对照。
- 如果用户后续明确要求输出键也用中文，应说明依据差异，再在其要求的验证阶段核对实际环境与下游支持；不提前宣称兼容，也不擅自改动既有运行代码的键名。
