# 明道云项目实施 skill：运行规则与平台依据

版本：设计草案 v0.2；更新日期：2026-10-22。
性质：将阶段方法串联起来的设计约定。未生成可安装 skill，未执行代码或实际业务案例。

## 1. 怎样选择当前工作

每轮先识别用户当前意图，再读取相关项目资料。一个项目可以同时有正在分析的需求和已经实施的功能，不能仅凭“项目处于搭建阶段”跳过新需求分析。

| 当前请求 | 优先处理 | 不自动附带的动作 |
|---|---|---|
| 从一句模糊想法开始 | 阶段 0、1，适量进入 2 | 不凭产品名字补成整套已确认需求 |
| 补充规则或纠正理解 | 更新阶段 2、3，分析对 4～7 的影响 | 不把追加一条文字当作全部变更完成 |
| 讨论某个实现方案 | 根据依据比较价值、限制和维护成本，更新设计草案 | 不把讨论方案视为平台执行授权 |
| 用户说“不懂”“不知道” | 解释相关概念与差别，提出条件明确的建议 | 不要求用户先自己写完整业务方案 |
| 要求搭建已确定内容 | 在明确环境、范围及已有授权内进入阶段 5 | 不重复询问每个已授权常规动作；不顺带上线其他功能 |
| 报错或效果不对 | 查现状与证据，定位到需求、设计、实现或环境问题 | 不以重新创建应用代替排查 |
| 用户手动改了应用 | 按 02 文档比较旧依据、现状与拟改方案 | 不无条件恢复旧配置 |
| 要求拉取或上传资料 | 执行项目文件同步并更新状态 | 不自动应用到 HAP，不更新已安装 skill |
| 用户说“继续” | 依据项目状态续做当前任务，重新识别新消息中的限制 | 不跨越用户保留的生成、实际搭建或验证边界 |
| 用户要求停止某部分 | 保存已完成与待处理状态，继续其仍要求的独立工作 | 不把局部停止扩大成取消整个项目 |

用户明确要求讲解时先回答问题；不强行将每个解释请求转成下一阶段推进。

## 2. 提问与默认建议

判断是否要问的标准是：答案不同，是否会明显改变业务含义、数据结构、访问范围、实施成本或当前操作。

- 会产生明显差别且没有可用依据：说明差别后提出问题，阻塞依赖它的决定，独立分析继续。
- 不影响当前工作：登记待确认事项，在相关阶段再问。
- 有低成本、可逆且符合已知目标的默认做法：提出建议及理由，可以推进草案；不能冒充用户已经确认。
- 用户已经明确决定：记录并使用。只有新证据或矛盾出现才重新讨论。
- 用户明确否定或撤销旧要求：标记旧要求被替代，不把新旧版本并列为当前有效规则。

不要每轮重复整套问题清单；不要把多个没有关联的问题合成一长段；不要通过假设消除关键未知。

### 客观引导的表达

合理质疑应包含依据、影响和建议。例如：“目前规则要求提交后不可修改，但另一个场景又要求直接更改已提交记录。需要明确更正机制，否则权限和历史记录的设计会冲突。可以选择撤回后修改，或新增一条更正记录；两者对追溯的影响不同。”

这是表达方式示例，不是本项目的真实业务规则，也不是要求未来所有业务都采用这两种机制。

回复应随任务变化：分析时突出判断与关键问题；实施时突出实际结果与差异；解释时直接回答。不要每次都机械输出相同标题和表格。

## 3. 什么时候可以进入实际操作

当前会话只授权设计。将来安装 skill 后，执行意图以当时用户指令和已授予范围为准。

| 情形 | 运行约定 |
|---|---|
| 读取项目资料、查官方文档、维护设计草案 | 在相应任务范围内直接进行，重要假设标明 |
| 用户只确认方案“可以”“看起来没问题” | 不仅凭这句话推断其要求立即写入平台，结合上下文确定意图 |
| 用户明确要求实施某范围 | 已明确的环境与范围内持续执行，不逐对象反复确认 |
| 操作会造成已授权范围外的删除、历史数据转换或外部通知 | 先明确影响、具体对象和可行方案，再解决缺失的授权；不把一般搭建授权无限扩大 |
| 当前工具不能完成 | 给出准确人工动作及验证依据，保持待执行状态；能够独立完成的工作继续 |
| 用户要求前期完成后再生成 | “完成”指所选范围的前期准备足够，不要求所有未来需求永久冻结；生成的具体对象有歧义时在跨入该动作前澄清 |

平台节点和代码块的“测试”也可能产生副作用。未来执行前检查实际代码是否写数据、发通知或调用外部服务；优先使用不影响真实业务的检查条件。

## 4. 中断后仍能使用的最小记录格式

下列是未来项目产物的数据约定，当前没有创建实际项目实例。字段可以按项目合并展示，不要求每次复制全套表格。

### 4.1 项目状态

| 字段 | 用途 |
|---|---|
| 项目标识、目录 | 防止切换会话后串项目 |
| 当前请求、本轮范围 | 解释现在为何做这件事 |
| 相关需求与修订 | 确定采用哪版业务预期 |
| 已完成及证据位置 | 区分结论与执行事实 |
| 待更新文件、待实施对象、待检查条目 | 保留多阶段不一致状态 |
| 未决问题及影响 | 避免重复问已回答的问题，防止忽略关键未知 |
| 下一步及前置条件 | 让“继续”有明确含义 |
| 平台环境与同步状态 | 记录已知事实；未知留空并说明 |

### 4.2 需求与设计关联

最小需求记录使用 01 文档约定的字段；设计对象记录自身逻辑编号、所实现需求、依据的规则修订及相关工作流。单一文件中可以通过段落链接关联，无需一开始建独立数据库。

变更后保留稳定编号并提升修订，不用更换编号掩盖它是同一个需求的变化。取消、被替代和历史版本保留可追溯记录，但不混入当前有效需求。

### 4.3 代码块参数说明

每个参数记录：节点标识、技术键、中文业务含义、值来源、类型与格式、必填与空值处理、示例、下游引用。代码另有版本及实现的规则编号。

输出结构在成功和失败路径上尽量保持稳定。项目可使用英文键配中文值和说明，例如 result 对应“执行结果”、message 对应“结果说明”、processed_count 对应“处理数量”；这是命名建议，不是平台预置字段。

不要把未知处理数量填成 0；0 表示已知没有处理，未知应按已约定的空值或独立状态表达。下游必须能区分成功无数据、业务拒绝、部分完成和技术失败。

## 5. 已查明的代码块文档依据

来源：[明道云官方代码块节点说明](https://help.mingdao.com/workflow/node-code-block/)，查阅日期 2026-10-22。以下是文档信息，未在用户目标环境验证。

| 文档线索 | 对设计的影响 |
|---|---|
| Python 示例从 input 读取，向 output 赋结果；文档要求实际输出键用英文以避免兼容问题 | 输入输出约定必须明确，中文可读性通过说明、注释和结果信息保留；不得断言所有中文键必然报错 |
| 文档列 Python 3.7.5、Node.js 10.16.3，并将 requests 列为可用 Python 模块 | 作为兼容性核对起点；不推断用户环境一定相同，也不猜测库具体版本 |
| 数组输入按字符串处理；多行记录来源有 100 行限制说明 | 明确输入序列化和数据完整性；不把这一条外推成所有 API 的分页上限 |
| 下游引用前需要节点有测试输出并保存 | 节点代码写完与下游参数可用是不同状态；未来需要有受控的操作步骤 |
| 节点执行失败可自动重试一次，设置可关闭 | 设计写入操作时应同时考虑平台重试与代码内重试，避免重复副作用 |

上述限制不能仅凭本地 Python 能运行就认定已满足。当前不运行样例，不安装依赖，不尝试节点测试。

### 中文偏好与兼容性的取舍

用户要求是“输入输出注释和参数这些最好用中文，便于查看和排错”。保留该偏好，并将官方输出命名提示作为实际证据：

- 业务说明、注释、参数含义、结果说明和错误解释使用中文。
- 输入键在目标环境支持时用中文；输出技术键默认英文，同时提供中文对照。
- 如果用户后续明确要求输出键也用中文，应说明依据差异，再在其要求的验证阶段核对实际环境与下游支持；不提前宣称兼容，也不擅自改动既有运行代码的键名。

### 尚未确定的信息

用户实际部署版本、节点运行时及库版本、运行时长与资源限制、外部访问条件、具体数据接口配额均未核实。它们属于后续项目的环境信息，不需要此时向用户一次索要全部内容。

## 6. 备份和发布的依据边界

[明道云备份还原文档](https://help.mingdao.com/application/backup-restore/)说明备份覆盖存在边界，例如不包含其他应用中修改本应用数据的工作流，角色成员配置也不在所列备份范围内。因此恢复计划应核对依赖，不能以“已备份”推断可完整回滚所有影响。

[明道云应用发布文档](https://help.mingdao.com/application/publish/)涉及终端和工作台等发布配置。项目交付中的版本记录、权限、流程启用和检查结果仍需单独处理，不以打开发布页面代替工程交付。

## 7. 设计成果如何转为 skill

设计目前覆盖：阶段 0～7 的方法、客观引导、产物保存、变更影响、恢复工作、代码块约定、实施与交付职责、GitHub 和经验复用。

收到明确生成要求后，按以下职责组织，具体目录名在生成时确定：

- 入口：触发范围、工作选择、读取状态、最重要的约束和资料路由。
- 需求与设计参考：阶段 1～4 的问题选择、分析方法和产物。
- 实施与交付参考：阶段 5～7、失败恢复与状态核对。
- 项目记录参考：02 文档的存储和变更规则。
- 代码块参考：本文件第 5 节及后续核对结果。
- 最小项目模板：项目状态与必要记录，按项目推进创建。

具体项目参数、平台 ID、客户规则、鉴权值和聊天原文不进入通用入口。未来调用其他搭建工具时继承当前项目范围，避免执行器绕过尚未确定的需求直接扩建。

设计有足够结构供下一步生成，但不等于已完成行为验证或已经保证所有环境可用。用户后续提出修改时，先更新本地设计；只有明确要求生成或验证时才进入对应动作。
